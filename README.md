# Clinic Agent 2.0

سامانه آغازین مدیریت کلینیک با رابط فارسی و راست‌چین، سازگار با موبایل و دسکتاپ.

## امکانات نسخه فعلی
- ورود با نقش‌های مدیر، پزشک و بیمار
- داشبورد و آمار پایه
- ثبت نوبت و مدیریت وضعیت آن
- فهرست بیماران و مدیریت کاربران
- دستیار اطلاعات پزشکی با اتصال اختیاری به API سازگار با OpenAI
- شناسایی اولیه چند عبارت هشدار و نمایش پیام ارجاع فوری
- ذخیره داده‌ها در SQLite

## اجرای محلی
نیازمند Node.js نسخه 20 یا بالاتر:

```bash
npm install
cp .env.example .env
npm start
```

سپس آدرس `http://localhost:3000` را باز کنید.

## حساب‌های نمایشی
این حساب‌ها در اولین اجرای پایگاه داده ساخته می‌شوند:

| نقش | ایمیل | رمز |
|---|---|---|
| مدیر | admin@clinic.local | Admin123! |
| پزشک | doctor@clinic.local | Doctor123! |
| بیمار | patient@clinic.local | Patient123! |

**بلافاصله پس از ورود آزمایشی، برای محیط واقعی حساب‌ها و رمزها را تغییر دهید.** این اطلاعات فقط برای دموی محلی هستند.

## فعال‌سازی دستیار هوش مصنوعی
1. فایل `.env` را بسازید.
2. `OPENAI_API_KEY` را در محیط سرور قرار دهید.
3. در صورت نیاز `OPENAI_MODEL` و `OPENAI_BASE_URL` را تنظیم کنید.
4. سرور را مجدداً اجرا کنید.

کلید API را هرگز در کد مرورگر، GitHub یا فایل عمومی قرار ندهید. کلید فقط باید در متغیرهای محیطی سرور تنظیم شود.

## انتشار در Render
1. این ZIP را از حالت فشرده خارج کنید.
2. تمام فایل‌ها را در یک مخزن جدید GitHub بارگذاری کنید.
3. در Render گزینه New > Blueprint را بزنید و مخزن را متصل کنید؛ فایل `render.yaml` تنظیمات اولیه را فراهم می‌کند.
4. در تنظیمات سرویس، `OPENAI_API_KEY` را به‌صورت Secret اضافه کنید.
5. برای نگهداری پایدار SQLite، دیسک پایدار Render لازم است. فایل Blueprint یک دیسک یک گیگابایتی تعریف می‌کند.

## نکات مهم قبل از استفاده واقعی
این پروژه یک MVP آموزشی/آغازین است و هنوز سامانه پزشکی آماده بهره‌برداری بالینی یا نگهداری داده واقعی بیمار نیست:
- ورود و نقش‌ها پیاده‌سازی پایه دارند؛ پیش از استفاده عمومی باید بازبینی امنیتی مستقل، سیاست رمز عبور قوی، MFA و کنترل دسترسی دقیق‌تر اضافه شود.
- شناسایی علائم خطر در این نسخه فقط تطبیق چند عبارت ساده است و ابزار تریاژ پزشکی معتبر نیست.
- دستیار هوش مصنوعی پاسخ عمومی تولید می‌کند؛ هنوز RAG واقعی، پایگاه دانش تأییدشده، ارجاع مستند و گردش‌کار تأیید پزشک پیاده‌سازی نشده است.
- پرونده الکترونیک پزشکی کامل، بارگذاری امن اسناد/تصاویر، نسخه الکترونیک و گزارش‌گیری حرفه‌ای هنوز در این MVP نیستند.
- پیش از ورود اطلاعات واقعی، الزامات قانونی حریم خصوصی و میزبانی داده‌های سلامت در کشور محل فعالیت باید بررسی شوند.
- از داده ساختگی استفاده کنید تا زمانی که ممیزی امنیت و انطباق انجام شود.

## سازگاری
رابط واکنش‌گراست و از مرورگرهای مدرن موبایل و دسکتاپ پشتیبانی می‌کند. برای دسترسی از گوشی و کامپیوتر، کافی است برنامه روی یک میزبان عمومی HTTPS مستقر شود.
